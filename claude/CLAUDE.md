## コミュニケーション

- 応答は日本語。コード内の識別子・コミットメッセージは英語
- 仕様が曖昧なときは推測で実装せず、選択肢を提示して確認する

## ワークフロー

- 複数ファイルにまたがる変更は、着手前に計画を短く提示する
- コミットは私が依頼したときだけ行う。git push は私が実行するので不要

## 破壊的な操作

IMPORTANT: 以下の操作は、確認を求めるのでもなく、実行自体を絶対にしないこと:

- git push --force を含む force push 全般
- rm -rf などの再帰的・不可逆な削除
- DB migration の適用（up / down / rollback いずれも）

これらが必要な場面では、実行すべきコマンドをコードブロックで出力するだけに
とどめること。実行するかどうかの判断と実行自体は私が行う。

## コーディング

- 既存コードの規約・パターンに合わせる。新しい流儀の持ち込みは提案してから
- 変更後は関連する単体テストと lint を実行する。Why: スイート全体は遅いので不要
- コードを説明するだけのコメントは書かない。「なぜ」が必要な箇所のみコメントする

## Git

- コミットメッセージは Conventional Commits（feat:, fix:, docs: ...）
- 1コミット1論点。無関係な変更を混ぜない
